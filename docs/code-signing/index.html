Code signing is planned and not active yet

OpenCue intends to use the free code signing for open-source projects provided by the SignPath Foundation. The application has not been approved or activated yet. Until then, the installers on GitHub Releases are not code-signed, and Windows or your browser may show a warning (see the Download page).

Team roles and responsibilities

OpenCue is maintained by The Crafted Tech. Currently the GitHub account TheCraftedTech holds all three roles; no other people have write or approval rights. If more people join, they will be listed here.

Because all roles are held by the maintainer today, changes are not yet checked by an independent second person. This is stated openly here instead of being hidden.

How changes are reviewed and releases are made

Today

  • The source code, the installer scripts (packaging/) and this website are in the public repository. Every change is visible in the Git history, and notable changes are listed in CHANGELOG.md.
  • Changes are made and checked by the maintainer before a release.
  • A release gets its version number (app/version.py) and is published on GitHub Releases.
  • The Windows installer is built on the maintainer's computer with packaging/build.ps1 (PyInstaller and Inno Setup) and uploaded as OpenCue-Setup-v<version>.exe. The licences of included third-party components are collected during the build (packaging/collect_licenses.py).
  • The installer is not code-signed yet.

Planned with SignPath

  • Release builds are created automatically from a tagged commit of the public repository (GitHub Actions workflow, to be added).
  • The built installer is submitted to SignPath for signing.
  • Every signing request must be approved by an Approver before the file is signed.
  • The signed installer is published on GitHub Releases. Its signature can be checked in Windows under the file properties, tab Digital Signatures.

Privacy

OpenCue runs on your computer. There is no account, no telemetry and no analytics. Except for the optional update check described below, this program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

What can connect, and when

  • Update check – At start, OpenCue asks api.github.com for the latest release. This is on by default and can be switched off in Settings → General. GitHub receives your IP address and the text “OpenCue/<version>” as user agent. Nothing is installed without your confirmation, and offline nothing happens.
  • Fixture library (GDTF Share) – Only when you open the online tab and sign in. Requests then go to gdtf-share.com with the account you enter. If you choose “Stay signed in”, the sign-in is stored encrypted on your computer.
  • DMX output – OpenCue sends lighting control data (DMX) to the targets you configure: Art-Net (on by default, to the Art-Net broadcast address in your local network), sACN (off by default) or a USB DMX interface.
  • Remote control – Off by default. When switched on, devices in your local network can connect with the password you set. The connection is not encrypted (plain HTTP).
  • Cameras and streams – Only the addresses you enter yourself.

Your shows, layouts and settings stay as files in the data folder on your computer. This website uses no cookies, no analytics and no third-party scripts; it only asks GitHub for release information and documentation.
